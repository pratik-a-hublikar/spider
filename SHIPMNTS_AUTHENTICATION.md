# Shipmnts Authentication Integration Guide

## Overview

The Spider application now includes an automated Shipmnts authentication system that allows generating refresh tokens directly through API endpoints, eliminating the need to run npm scripts manually.

## Architecture

The authentication system consists of:

1. **AuthenticationScriptExecutor** - Java component that executes the Node.js authentication script
2. **ShipmntsService** - Service interface with authentication capabilities
3. **ShipmntsServiceImpl** - Implementation that orchestrates the authentication flow
4. **ShipmntsController** - REST endpoints to trigger authentication and fetch data

## How It Works

### Traditional Flow (Before)
```
User runs: npm run shipmnts:authenticate
    ↓
Playwright opens Chrome browser
    ↓
User logs into Shipmnts
    ↓
Refresh token captured and saved to .env
    ↓
Backend restarted to load new token
    ↓
User calls /fetch API
```

### New Automated Flow (After)
```
User calls: POST /api/v1/identity/authenticate
    ↓
Backend triggers Node.js script via AuthenticationScriptExecutor
    ↓
Playwright opens Chrome browser
    ↓
User logs into Shipmnts
    ↓
Refresh token automatically saved to .env
    ↓
User restarts backend
    ↓
User calls GET /api/v1/identity/fetch
```

## Setup Instructions

### 1. Prerequisites

Ensure the following are installed:
- Java 21+
- Maven 3.8.9+
- Node.js 18+
- Chrome or Chromium browser
- PostgreSQL/MySQL

### 2. Environment Configuration

Create or update `.env` file in the project root:

```env
# Database Configuration
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_password
POSTGRES_DB=spider
POSTGRES_PORT=5432

# Redis Configuration
REDIS_PORT=6379

# Shipmnts Configuration
SHIPMNTS_CLIENT_ID=client_01J7DZVQXBTQZGGAE5WSYNQYRN
SHIPMNTS_EMAIL=your-email@example.com
SHIPMNTS_PASSWORD=your-password
SHIPMNTS_ORGANIZATION_ID=your-org-id  # Optional

# These will be auto-generated by the authentication flow
SHIPMNTS_REFRESH_TOKEN=
SHIPMNTS_ORGANIZATION_ID=
```

### 3. Build the Project

```bash
# Build backend
mvn clean install

# Install frontend dependencies
cd ui/react-auth-skeleton
npm install
```

### 4. Start Services

```bash
# Start backend
cd identity
mvn spring-boot:run -Dspring-boot.run.arguments="--spring.profiles.active=dev"

# In another terminal, start frontend
cd ui/react-auth-skeleton
npm run dev
```

## Using the Authentication Endpoints

### Endpoint 1: Generate Refresh Token

**Request:**
```bash
curl -X POST http://localhost:8080/api/v1/identity/authenticate \
  -H "Authorization: Bearer <your-jwt-token>" \
  -H "Content-Type: application/json"
```

**Response:**
```json
{
  "success": true,
  "data": "Authentication completed. Please restart the backend to load the new refresh token.",
  "message": "success"
}
```

**What Happens:**
1. Browser window opens automatically
2. Follow Shipmnts login flow
3. Complete any CAPTCHA/MFA prompts
4. Refresh token is captured and saved to `.env`
5. Response confirms completion

**Note:** You have 5 minutes to complete the login. After that, the script times out.

## Important Notes

### After Authentication

⚠️ **IMPORTANT**: After running the authentication endpoint, you MUST restart the backend service:

```bash
# Stop the running backend (Ctrl+C in the terminal)

# Restart it
mvn spring-boot:run -Dspring-boot.run.arguments="--spring.profiles.active=dev"
```

This ensures the new refresh token from `.env` is loaded into the application.

### Troubleshooting

#### Issue: "Shipmnts authentication failed: Client not found"
**Solution:** 
- Verify `SHIPMNTS_CLIENT_ID` in `.env` is correct
- Ensure it's not expired or revoked in Shipmnts

#### Issue: "Timed out waiting for Shipmnts authentication"
**Solution:**
- The browser window may be waiting for user interaction
- Check the Chrome window that opened for CAPTCHA, MFA, or error messages
- Complete any prompts manually within 5 minutes
- Retry if timeout occurs

#### Issue: "Chrome/Chromium not found"
**Solution:**
- **Windows**: Chrome is usually auto-detected. Ensure it's installed.
- **macOS**: Chrome should be auto-detected. If not:
  ```bash
  brew install chromium
  ```
- **Linux**: Install Chromium:
  ```bash
  sudo apt-get install chromium-browser
  ```

#### Issue: "SHIPMNTS_REFRESH_TOKEN is blank"
**Solution:**
- The authentication script didn't capture the token
- Check the Chrome window for any error messages during login
- Verify credentials are correct
- Try authentication again

#### Issue: Backend can't find the script
**Solution:**
- Ensure the project structure is intact
- Verify `ui/react-auth-skeleton/scripts/shipmnts-authenticate.mjs` exists
- Check that Node.js is installed and in PATH

### Script Execution Details

The authentication script:
- Uses Playwright for browser automation
- Requires Chrome/Chromium to be installed
- Opens a visible browser window (not headless by default)
- Captures the refresh token from the authentication response
- Saves it securely to `.env` with proper file permissions (mode 0o600)
- Handles both OAuth and credential-based login flows
- Supports MFA and CAPTCHA (user completes these manually)
- Times out after 5 minutes of waiting for authentication

## Integration with Frontend

The authentication flow can be triggered from the React frontend:

```javascript
// services/authService.js
async function generateShipmntsToken() {
  try {
    const response = await axios.post(
      '/api/v1/identity/authenticate',
      {},
      {
        headers: {
          'Authorization': `Bearer ${getAuthToken()}`
        }
      }
    );
    
    // Show success message and prompt for backend restart
    showNotification('Please restart the backend to load the new token');
    
    return response.data;
  } catch (error) {
    showError('Authentication failed: ' + error.message);
    throw error;
  }
}

// Usage in a React component
const handleAuthenticate = async () => {
  setLoading(true);
  try {
    await generateShipmntsToken();
  } finally {
    setLoading(false);
  }
};
```

## Security Considerations

1. **Credentials Storage**: Never commit credentials to version control
   - Use `.env` for local development
   - Use environment variables in production
   - Use secrets management (AWS Secrets Manager, Azure Key Vault, etc.)

2. **Refresh Token Security**:
   - Refresh tokens are saved to `.env` with restricted permissions (0o600)
   - Ensure `.env` is in `.gitignore`
   - In production, use a secrets management service

3. **Access Control**:
   - Authentication endpoint requires valid JWT token
   - Use role-based access control (RBAC) to restrict who can call this endpoint
   - Consider adding an admin-only restriction

4. **Rate Limiting**:
   - Consider implementing rate limiting on the authentication endpoint
   - Prevents brute force attacks

## API Reference

### POST /api/v1/identity/authenticate

Generates a new Shipmnts refresh token.

**Requirements:**
- Valid JWT Bearer token
- Correct Shipmnts credentials in `.env`
- Chrome/Chromium installed
- Network access to Shipmnts servers

**Response Codes:**
- `200 OK` - Authentication completed successfully
- `400 BAD_REQUEST` - Invalid configuration
- `408 REQUEST_TIMEOUT` - Script execution timed out
- `502 BAD_GATEWAY` - Shipmnts API returned an error
- `503 SERVICE_UNAVAILABLE` - Missing required configuration

### GET /api/v1/identity/fetch

Fetches the current user profile from Shipmnts.

**Requirements:**
- Valid JWT Bearer token
- Valid SHIPMNTS_REFRESH_TOKEN in `.env`
- Network access to Shipmnts GraphQL endpoint

**Response Codes:**
- `200 OK` - User profile fetched successfully
- `400 BAD_REQUEST` - Invalid GraphQL query
- `502 BAD_GATEWAY` - Shipmnts API returned an error
- `503 SERVICE_UNAVAILABLE` - Missing SHIPMNTS_REFRESH_TOKEN

## Frequently Asked Questions

**Q: Do I need to restart the backend after authentication?**
A: Yes, the refresh token is read from `.env` at startup. Restart to load the new token.

**Q: Can I run authentication multiple times?**
A: Yes, each run generates a new token. The old token is replaced.

**Q: What if I see "CAPTCHA not solved"?**
A: The browser window is waiting for you to complete the CAPTCHA manually. Check the Chrome window.

**Q: Can I schedule authentication to run automatically?**
A: You can create a scheduled job that calls the API endpoint periodically. Use your application scheduler (Quartz, Spring Task Scheduling, etc.).

**Q: How long does authentication take?**
A: Typically 1-2 minutes if Shipmnts credentials are correct and no CAPTCHA/MFA is required. Timeout is set to 5 minutes.
